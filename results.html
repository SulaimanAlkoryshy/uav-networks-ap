UAV-NIDD — Access Point (Case 2) Intrusion Detection — Results

A classical-ML IDS on the AP scenario (packet-level Wi-Fi capture, 631,356 packets, 10 attacks + Normal), built in 6 stages. Two paths: report = the GP report's method (keeps every column, ANOVA top-25), and search = the honest version (drops the time/order and IP columns, tree-importance top-25). The goal is a trustworthy score, not the biggest number.

Stage 1 — Preprocessing, feature selection & shortcut check

The AP file is messy: the label column is headed 'Normal', 'Evil Twin' is spelled 'Ewil Twin', column headers are shifted against their contents, and cells mix numbers, hex (0x..) and IP addresses. Hex is parsed, other text becomes -1 (dropping those rows would delete 100% of Evil Twin, MITM, Reconnaissance and Replay). Split 80/20 stratified (seed 42), PCC > 0.85, top-25.

Leakage: the column frame.time_relative (really the capture timestamp) alone reaches macro-F1 0.92 — each attack was captured in its own session, so time identifies the class. The search path drops it with the other time/order + IP columns; the report path's ANOVA picked all of them.

Stage 2 — Class balancing

AP imbalance: Brute-Force 172,509 vs Reconnaissance 40 (≈ 4,300:1). We compared no-balancing, RandomUnder+Borderline-SMOTE, and class_weight (RF), judged by test macro-F1.
